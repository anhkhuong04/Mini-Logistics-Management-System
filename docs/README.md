## Ownership and update rules

- Update product/domain documents when user-visible behavior or business invariants change.
- Update architecture/data documents when module boundaries, persistence guarantees, or important runtime flows change.
- Add or supersede an ADR for a durable decision with meaningful alternatives or operational consequences.
- Update the Partner API reference, examples, changelog, and generated OpenAPI together when its public contract changes.
- Avoid progress percentages, current test counts, copied source trees, and speculative roadmaps. Link to the authoritative code or command instead.
- Keep agent-only working rules in [`AGENTS.md`](../AGENTS.md) and [`.agents/`](../.agents/); do not duplicate them here.
